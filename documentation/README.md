# Petroleum user documentation

How to use Petroleum to design sounds and render them. For an overview of the
project and how to build and launch it, start with the
[project README](../README.md).

## Where to find things

- **[Diesel language guide](../DIESEL.md)** - the complete reference for the
  `.dsl` text format: syntax, node fields, connections, macros, embedded
  samples, and the full node reference table. This is the most detailed
  documentation currently available, and it describes every node and port that
  the editor exposes, under the same names the editor uses.
- **In-app documentation** - the editor ships with its own documentation
  screen. Every node has a "?" button in its header that opens a description,
  a longer article, and a worked wiring example for that node. The same screen
  carries guide articles for the editor's own features, and can be browsed
  from its index without going through a node.
- **[Rendering from the command line](../README.md#render-from-the-command-line)** -
  turning a saved patch into a WAV file with no editor and no display.

## The three screens

**Quick Sounds** generates a complete patch from a category, such as Pickup,
Laser or Explosion, and a seed. It gives you a waveform preview, one slider per
macro, Play, Mutate and Export WAV, and a history of the last twenty sounds
rolled. A generated sound is a real patch, not a preset, so "Open in graph
editor" hands you the whole graph to take apart and modify.

**The graph editor** is where patches are built: nodes are added from a menu,
dragged around the canvas, and wired port to port. Knobs on unconnected input
ports set a fixed value; connect something to a port and the connection takes
over. Any knob can be promoted to a macro, which becomes a labelled slider for
the patch as a whole, and becomes an input port if the patch is later used as a
node inside another patch.

**The documentation screen** is the in-app reference described above.

## Saving and sharing

Patches save as `.ptr`, a self-contained archive, or as `.dsl`, the Diesel text
format. The two convert both ways without losing anything, so a patch can be
built visually, saved as text, edited in a text editor or generated by a
script, and opened again in the editor.

Nothing is ever saved by reference. An imported sample is written into the
patch as audio data, and a patch used as a node is embedded by value, so a
patch file always opens on its own on someone else's machine.

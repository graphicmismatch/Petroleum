# Petroleum

Petroleum is a Java audio synthesis engine and visual patch editor. Sounds are
built as a graph of nodes - oscillators, filters, effects, envelopes, mixers -
wired together on a canvas, played back live or rendered to a WAV file. The
same patches have a plain-text form, Diesel, that can be hand-written,
generated by a script, kept under version control and rendered from the command
line with no editor and no display.

The only third-party dependency is JavaFX.

## Features

- **Oscillators and noise** - analogue waveforms, noise generators, wavetables,
  dual oscillators and wavefolding.
- **User-defined waveforms** - write an expression such as
  `sin(x) + 0.3*sin(3*x)` and play it as an oscillator.
- **A full node palette** - filters, delay, reverb, distortion, compression,
  bitcrushing, choruses and phasers, mixers, envelopes, ramps, and conditional
  and trigger-driven logic nodes.
- **Granular, spectral and physical synthesis** - grain-based sample playback
  and live freeze, spectral freeze, spectral gating and phase-vocoder pitch
  shifting, and physically modelled string and modal resonators.
- **Multisample instruments** - keyed sample zones with a volume envelope.
  Pitch is carried in Hz throughout, so tuning is fully microtonal with no
  separate tuning system.
- **Sequencing** - a 2/4/8/16-channel tracker with per-note pitch and timing
  effects, a polyphonic piano roll with velocity, and MIDI file import,
  export and playback.
- **Patches as nodes** - any saved patch can be used as a node inside another,
  so your own instruments and effects are ordinary files. Macros on the inner
  patch become its input ports.
- **Generated sounds** - seeded category generators (Pickup, Laser, Explosion
  and others) produce a real patch rather than a preset, so a generated sound
  opens in the editor ready to take apart.
- **Cross-platform audio** - playback and WAV rendering through
  `javax.sound.sampled`, with configurable sample rate, bit depth, channel
  count, peak normalisation and silence trimming. No native dependencies.
- **Native installers** - build a `.msi`, `.dmg` or `.deb` that bundles its own
  Java runtime, so the application runs without a JDK installed.

## Requirements

- JDK 17 or newer.
- Maven 3.
- JavaFX 21, resolved automatically as a per-platform Maven dependency. The
  same `pom.xml` works unmodified on Windows, macOS and Linux.

Running the editor needs a real display, and live playback needs a real audio
device. Rendering to a WAV file needs neither.

## Building and running

```
mvn compile
mvn javafx:run
```

The first build must run online so the JavaFX artifacts download; afterwards
`mvn -o compile` works offline.

To build a native installer instead, so that Petroleum can be installed and
launched like any other desktop application:

```
mvn -Pnative-windows package
mvn -Pnative-mac package
mvn -Pnative-linux package
```

The installer is written to `target/dist/`. Each profile only works when run on
the OS it targets, since there is no cross-building. `-Djpackage.type=app-image`
produces a runnable directory and skips the installer step, which needs no
tooling beyond the JDK; `msi` and `exe` need the WiX Toolset, and `deb` and
`rpm` need `dpkg-deb` or `rpmbuild` on `PATH`. As with `mvn package`, the first
run must be online.

## Making a sound

The editor opens on one of three screens.

**Quick Sounds** rolls a complete patch from a category and a seed, with a
preview, a slider per macro, Play, Mutate and Export WAV. Opening one in the
graph editor gives you the entire graph to modify.

**The graph editor** is where patches are built: add nodes from the menu, wire
them port to port, and set unconnected inputs with their knobs. Promote a knob
to a macro to get a labelled slider for the patch as a whole.

**The documentation screen** is a built-in, searchable reference. Every node
also has a "?" button in its header that opens a description and a worked
wiring example for that node.

## Render from the command line

`render` runs headless, without JavaFX:

```
java -cp target/classes Petroleum.Main render song.dsl -o song.wav
```

| Option | Meaning |
|---|---|
| `-o`, `--output <file>` | WAV file to write. Required. |
| `-d`, `--duration <sec>` | Length in seconds. Defaults to running until a Recording End node fires or a one-shot patch finishes. |
| `--max-duration <sec>` | Ceiling for a render with no `--duration`, so a Recording End that never fires still stops. Default 600. |
| `--rate <hz>` | Sample rate. Default 44100. |
| `--bits <8\|16\|24\|32>` | Bit depth. Default 16. |
| `--channels <1\|2>` | Channel count. Default 2. |
| `--normalize` | Scale the peak to just under full scale. |
| `--trim` | Cut leading and trailing silence. |

A patch that plays forever and has no Recording End node is rejected unless
`--duration` is given.

## Patch formats

Patches save as `.ptr`, a self-contained archive of the patch and any samples
it uses, or as `.dsl`, the Diesel text format. The two convert both ways
without losing anything. Legacy `.jsynth` files still open.

A minimal Diesel patch:

```c
// A 220 Hz sine drone.
patch "Drone" {
    "LFO Sine" lfo { .frequency = 220; }
    "Audio Out" out;

    lfo.out -> out.in;
}
```

Nothing is ever saved by reference. An imported sample is written into the
patch as audio data and a patch used as a node is embedded by value, so a patch
file always opens on its own on another machine.

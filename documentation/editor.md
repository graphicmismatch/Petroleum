# The graph editor

The editor is where patches are built. This covers moving around a patch,
working with ports and macros, and the commands available from the menus.

If you have not built a patch before, start with
[Getting started](getting-started.md).

## The window

The **menu bar** carries File, Edit, View, Options and Help.

The **toolbar** along the top has Quick sounds, undo and redo, the zoom
controls with the current zoom level, and **Organize**.

The **canvas** fills the middle. Right-click anywhere on it to add a node.

The **Macros** panel on the right lists the knobs you have promoted, and the
**Map** below it shows the whole patch in miniature with your current view
marked, which is the quickest way to find your way around a large graph.
**Open** expands it.

The **transport** along the bottom has Play and Stop, Export to WAV, and
shortcuts for saving and opening a patch.

## Nodes

Right-click anywhere on empty canvas to open a categorised menu of every node
type. The node is placed at the point you clicked.

Drag a node by its title header to move it. A handle in its bottom-right corner
resizes it, which is worth doing for nodes with a formula box or many ports, so
more is visible at once.

Click a node or a wire to select it, shown by a highlighted border, and press
Delete or Backspace to remove whichever is selected. Right-clicking a node's
header offers the same delete from a menu.

Each node shows its input ports on the left and its output ports on the right.
The **?** button in a node's header opens that node's own documentation, with a
description and a worked wiring example. This is usually faster than looking a
node up elsewhere, and it is the best way to find out what an unfamiliar port
expects.

### Wiring

Press and drag from an output port on a node's right edge to an input port on
another node's left edge, then release.

Dropping a wire on empty canvas instead of on a port opens the add-node menu at
that point and wires the new node's first input to whatever you dragged from.
This is the fast way to build a chain, since you never have to aim at a small
port circle.

Right-click an input port to delete whatever wire is plugged into it.

A patch must end at exactly one **Audio Out** node, and it cannot contain a
loop - a signal cannot feed back into something that produces it, directly or
through a chain.

### Knobs

Every input port has its own slider and number field beneath the node, seeded
to that port's default. Drag the slider or type a number to set it, with no
Constant node needed.

Wiring something into that port takes over automatically, and the slider greys
out to show it is no longer in control. Deleting the wire hands control back,
restoring the value the slider last showed.

### Macros

Every knob row, and every Constant node, ends in a small button showing **+**
while it is not yet a macro. Click it and give the macro a name, and that knob
appears in the Macros panel as its own labelled slider, alongside every other
promoted control.

Once promoted, the button shows the macro's name and opens a menu to rename it,
change its slider's range, or remove it again. A macro whose target has since
been disconnected or deleted is labelled "not driving anything" and its slider
is disabled, rather than silently doing nothing.

Macros matter beyond convenience. When a patch is used as a node inside another
patch, each of its macros becomes an input port on that node. Deciding what to
promote is deciding what your instrument or effect exposes to whoever uses it.

## Moving around

| Action | How |
|---|---|
| Zoom | Ctrl and scroll, the toolbar buttons, or Ctrl+= and Ctrl+- |
| Reset zoom | **View > Reset Zoom** |
| Return to the patch | **View > Center View** |
| Tidy the layout | **Organize** in the toolbar, or **View > Organize Layout** |

Ctrl and scroll zooms centred on the cursor, which is how you get into a tight
cluster of ports without losing your place. The toolbar's **-** and **+** zoom
by the same steps but centred on the middle of the view, and the percentage
between them is the current level.

**Center View** scrolls so the whole patch is centred at the current zoom.

The canvas has no fixed size. It grows in every direction as nodes pass its
edge, and dragging a node, wire or resize handle to the edge of the window
scrolls the view and keeps expanding the work area for as long as you hold it
there, so a large patch never runs out of room.

**Organize** arranges nodes into left-to-right columns following the signal
flow, sources on the left and the output on the right, then centres the view on
the result. It is a single undo step, so Ctrl+Z puts everything back. It is
most useful on a patch written by hand in Diesel or generated by a script,
where nodes have no positions and arrive stacked at the origin.

## Undo

Every structural edit can be undone: adding and deleting nodes, wiring and
unwiring, moving things, and macro changes. Ctrl+Z undoes, Ctrl+Shift+Z redoes.

## Playing

**Play** builds a patch from the current graph and starts it from the
beginning; **Stop** halts it. A patch that never ends keeps playing until
stopped, and one built around a one-shot envelope plays once and finishes on
its own.

Edits made while it is playing are picked up immediately: the running patch is
rebuilt and swapped in on the fly, so you can drag a cutoff slider or rewire
something and hear the result without stopping.

Under **Options**, you can choose the **Output Device** and **Input Device**,
set **Playback Quality** and **Latency**, and set a **Render Limit**. Lower
latency is more responsive but more likely to break up; raise it if playback
stutters.

## Reusing a patch as a node

The **Patches** category has two entries. **Load patch as node...** picks a
saved `.ptr` file and drops it in as a single node: its Audio Out becomes the
node's output, and each of its macros becomes an input port. **New Subpatch**
creates an empty one in place instead, holding only an Audio Out.

Either way, the node's **Edit** button opens the inner patch in the editor, and
**Done** returns you to the outer one.

This is how you build an instrument or an effect once and use it everywhere.
The patch is embedded by value rather than linked, so a patch that uses it
still opens on a machine that has never seen the original.

## Keyboard shortcuts

### File

| Shortcut | Action |
|---|---|
| Ctrl/Cmd+S | Save Patch |
| Ctrl/Cmd+O | Open Patch |

### Edit

| Shortcut | Action |
|---|---|
| Ctrl/Cmd+Z | Undo |
| Ctrl/Cmd+Shift+Z | Redo |
| Delete / Backspace | Delete selection |

### View

| Shortcut | Action |
|---|---|
| Ctrl/Cmd+= | Zoom in |
| Ctrl/Cmd+- | Zoom out |

### Tracker grid

| Keys | Action |
|---|---|
| Z S X D C V G B H N J M | One octave of white and black keys |
| Q 2 W 3 E R 5 T 6 Y 7 U I 9 O 0 P | One octave up from those |
| Arrow keys | Move the cursor |
| Home / End | Jump to the first or last step |

The same list is in the application under **Help > Keyboard Shortcuts**.

## Built-in documentation

**Help > Documentation** opens the reference that ships with the editor. It has
an article for every node you can place, each with a description and a worked
wiring example, plus guide articles on the editor's own features. Any node's
**?** button jumps straight to its article.
